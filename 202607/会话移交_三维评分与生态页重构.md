## 四、已经确认的评分口径

### 1. 最小爽环认知负担

评价玩家理解 `Random → Put → C₁`、判断本次结果好坏所需的学习、记忆与推理成本。

不包括：

- BD 构筑复杂度
- 长期资源规划
- 长期策略深度
- 战斗系统在多轮后的复杂度

只评价最小爽环中的即时理解成本。

### 2. 单 Spin 玩家介入强度

“单 Spin”从启动本次 Spin 开始，持续到 `Spin_Result` 封闭为止。

计入：

- Random、Put、C₁、C₂ 阶段中发生的玩家操作
- C₂ 过程中发生的操作

不计入：

- BD
- 下一轮准备
- 长期构筑
- 单纯由棋盘大小、敌人数量或战斗系统复杂度造成的认知压力

棋盘大、敌人多、长期系统复杂，都不能直接提高“单 Spin 玩家介入强度”。

### 3. C₂ 二次揭晓深度

`C₂` 深度衡量的不是动画长度，而是 `C₁` 之后关键结果信息随时间释放、使玩家修正预测的结构。

- 0 分：无独立 C₂。C₁ 后直接产生 `Spin_Result`。
- 1 分：确定结果展示。答案在 C₁ 后已经封闭，C₂ 只播放已知结果。
- 2 分：单次关键揭晓。至少释放一个此前未知的关键信息，使玩家明显更新一次预测。
- 3 分：多阶段递进揭晓。前段结果改变后段条件，玩家多次修正预测。
- 4 分：链式持续揭晓。结果继续生成新的结果节点，链条长度或结束时间事前可能未知。

注意：

- 攻击次数多、动画长，不等于 C₂ 分数高。
- 战斗系统复杂，不等于 C₂ 更深。
- 评分表示“在二次揭晓方向上的深度”，不直接表示设计质量。
- `PegLotto! Demo` 的弹珠过程应记 3 分，因为它有多阶段反馈；同时单独标记“重置风险”，不能把风险混入深度分数。

### 4. 档位映射

- 0—1：低
- 2：中
- 3—4：高

页面同时显示原始分数和低／中／高档位。

### 5. 未知分数

若游戏缺少当前二维视图任一轴的评分：

- 不得假装放在坐标中央。
- 放入图外“待定位游戏”区域。
- 显示缺少的维度，如“缺认知评分”“缺操作评分”“缺 C₂ 评分”。
- 当待定位游戏为 0 时，不显示该区域。

当前 26 款游戏都已经给出建议分数，正常迁移后该区域应隐藏。

## 七、生态页三视图设计

### 核心实施边界：基于新三维评分生成全新生态图

本阶段必须把“新生态图”作为独立实施成果，不得只在旧生态图上改标题、替换轴名，或继续读取旧标签推导坐标。

唯一坐标数据源：

```js
const ecosystemViewAxes = {
  "operation-c2": {
    x: "spin_intervention",
    y: "c2_reveal_depth"
  },
  "cognition-operation": {
    x: "cognitive_load",
    y: "spin_intervention"
  },
  "cognition-c2": {
    x: "cognitive_load",
    y: "c2_reveal_depth"
  }
};
```

数据流必须保持单向：

`category-ecosystems.json` 中的 `dimensions` → 当前二维视图投影 → 节点位置 → 右侧详情。

实施约束：

- 三个视图都读取同一款游戏的同一组三维分数，不为每个视图重复保存独立 `x/y`。
- 0—4 分在三个坐标轴上采用一致的等距刻度与语义；低／中／高档位只负责解释和节点辅助表达。
- 节点重叠时可以计算轻微的视觉避让偏移，但偏移不得改写评分，也不能让节点跨越其真实分数格。
- 销量档位、Steam 用户评价、`Show_TP`、`C₁`、敌方空间及其他标签继续显示和参与筛选，但绝不进入坐标计算。
- 当前品类原型决定生态图的数据集合；四个品类原型分别展示其所属游戏，合计必须仍为 26 款。
- 缺少当前视图任一坐标的数据放到图外“待定位游戏”区域，明确列出缺失维度；全部游戏评分完整时隐藏该区域。
- 旧 `x/y` 仅可在迁移期保留为 `legacy` 对照或回滚数据；新生态图运行时不得读取，验收完成后再决定是否删除。

新生态图应完整包含以下可见区域：

1. 当前品类与三视图切换器。
2. 当前视图的 X／Y 轴名称、0—4 刻度和端点含义。
3. 使用新评分投影的游戏节点；节点继续显示游戏图标、名称、认知档位、销量档位和 Steam 评价。
4. 仅负责筛选与解释的 `Show_TP`、`C₁`、敌方空间等标签区。
5. 与当前游戏同步的右侧三维详情。
6. 仅在存在缺分数据时出现的“待定位游戏”区域。

这部分的完成标准是：修改任一游戏的三维评分后，三个二维视图的对应投影和右侧详情都自动更新；无需再手工维护旧坐标。

- Y 轴：C₂ 二次揭晓深度，0 → 4。
- 节点额外展示认知档位：低／中／高。

### 视图 2：认知 × 操作

- X 轴：最小爽环认知负担，0 → 4。
- Y 轴：单 Spin 玩家介入强度，0 → 4。
- 节点仍保留 C₂ 分数或档位的简洁辅助表达。

### 视图 3：认知 × 演绎

- X 轴：最小爽环认知负担，0 → 4。
- Y 轴：C₂ 二次揭晓深度，0 → 4。
- 节点仍保留操作分数或档位的简洁辅助表达。

- 当前品类原型
- 当前标签筛选

- 右侧详情焦点

## 八、C₂ 二次揭晓深度说明页

### 插入位置

放在“体验模型”页的 `C₂` 字段详情中，作为独立子页面或详情子面板。

入口与返回必须双向关联：

- 从 `C₂` 字段详情进入“C₂ 二次揭晓深度”。
- 从深度说明页返回原 `C₂` 字段位置，而不是返回体验模型页顶部。

### 核心定义

页面必须明确写出：

> C₂ 深度衡量的不是动画长度，而是 C₁ 之后关键结果信息随时间释放、使玩家修正预测的结构。

并明确：

> 攻击次数多、动画时间长，不等于 C₂ 分数高。只有过程真正释放新信息，并继续改变玩家对 C₁ 兑现程度的预测，才构成更深的二次揭晓。

### 统一横向时间轴

默认同时完整显示 0—4 分五行，五行共享同一条时间尺度：

`C₁ 建立价值锚点 → Spin_Result 最终封闭`

节点类型：

- C₁ 价值锚点
- 确定动画
- 关键揭晓点
- 阶段反馈
- 链式触发
- Spin_Result

封闭程度：

- 0 分：立即封闭
- 1 分：已经封闭，只在播放
- 2 分：一个关键节点后封闭
- 3 分：分阶段逐步封闭
- 4 分：链式展开后封闭

### 统一示例

五行统一使用：`C₁ 都产生 20 点基础攻击`。

分别演示 0—4 分如何从同一价值锚点展开，避免不同示例导致用户误以为评分由题材或数值大小决定。

### 交互

- 点击 0—4 分切换聚焦说明。
- 默认不隐藏其他四行，只改变高亮。
- 交互应保持整张时间轴始终可见。
- 不使用 `html-viz`。
