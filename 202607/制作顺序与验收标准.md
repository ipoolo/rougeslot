## 0. 已确认的核心原则

### 0.1 统一术语

固定使用以下四层术语：

1. **体验模型**
2. **机制母型**
3. **品类原型**
4. **品类变体**

不再使用“机制母体”。

### 0.2 最新核心公式

```text
P(t) ⟦
  [ Random @ Pool_Symbol → Put @ Show_TP → Combo(C₁ → C₂?) @ Show_TP ]ₙ
  → BD
⟧
```

核心边界：

- `P(t)` 是可选的外层目标压力域，不是第五个操作步骤。
- `P(t)` 的目标检查周期必须与 `N` 分开记录。
- `Random` 只作用于 `Pool_Symbol`。
- `Random` 输出 `SingleSpin_Symbol`。
- `Put` 把 `SingleSpin_Symbol` 放入 `Show_TP`。
- `Put` 与 `Combo` 共同承载于 `Show_TP`。
- `Show_TP` 表示承载空间的类型。
- `Show_State` 表示某一次 Spin 在该空间中形成的具体状态。
- `Combo(C₁→C₂?)` 在 `Show_TP / Show_State` 上先完成 C₁ 判定，再按需执行 C₂ 结果演绎并结算。
- 多次 Spin 后进入 `BD`，BD 再影响后续循环。

### 0.3 原型图谱

第二部分采用**原型图谱**，不限制为单棵树：

- 多个机制母型可以并列存在。
- 一个机制母型可以派生多个品类原型。
- 一个品类原型可以派生任意数量和深度的品类变体。
- 品类原型可以指定一个主机制母型，并组合其他机制母型的部分能力。
- 所有机制母型、品类原型和品类变体都必须映射回体验模型公式。

### 0.4 完全独立

新版所有文件放在 `202607/` 内：

- 不读取旧版 `data/`。
- 不引用旧版 `lib/`。
- 不复用旧版页面脚本。
- 不修改旧版网页。
- 旧内容只能作为人工整理时的参考资料。

# 二、分阶段制作内容与验收标准

## 阶段 1：冻结体验模型公式

### 制作内容

建立一份正式公式规范，至少包含：

1. 单次 Spin 主公式。
2. 多次 Spin 到 BD 的循环公式。
3. 每个操作的输入与输出。
4. 第一峰、第二峰分别覆盖的流程。
5. `@` 运算符的正式定义。
6. `Show_TP` 与 `Show_State` 的区别。
7. BD 可以影响下一轮公式中的哪些部分。
8. `P(t)` 的目标、期限、差距、失败代价，以及它与 `N` 的边界。

建议正式数据流：

```text
Pool_Symbol
  ──Random──>
SingleSpin_Symbol
  ──Put @ Show_TP──>
Show_State
  ──Combo(C₁→C₂?) @ Show_TP──>
Spin_Result
```

### 交付物

- `model/experience-model.json`
- `content/formula.md`
- 一张单次 Spin 数据流图
- 一张多次 Spin—BD 循环图

### 验收标准

- [ ] Random 的直接作用对象只有 `Pool_Symbol`。
- [ ] Random 的输出被明确命名为 `SingleSpin_Symbol`。
- [ ] Put 的输入、承载空间和输出均有定义。
- [ ] Combo 明确读取 `Show_TP / Show_State`。
- [ ] 第一峰与第二峰在公式中能被准确标出。
- [ ] P(t) 作为外层边界包裹完整循环，且不与 N 混用。
- [ ] BD 与下一轮 Spin 之间存在清楚的反馈关系。
- [ ] 公式中不存在未定义符号。
- [ ] 同一个概念没有多个名称。

### 阶段门

公式冻结后，才进入变量字典和网页制作。后续若修改公式，需要同步触发对应内容的版本升级。

## 阶段 4：定义约束与继承规则

### 制作内容

原型节点对公式变量只能使用统一操作：

| 操作 | 含义 |
|---|---|
| `inherit` | 完全继承父级 |
| `default` | 提供先验默认值，但允许下级改变 |
| `restrict` | 收窄父级允许的取值范围 |
| `fix` | 固定为具体值 |
| `override` | 用新的定义替换父级定义 |
| `extend` | 保留父级并增加新能力 |
| `compose` | 组合另一机制母型的部分先验 |

每个节点需要区分：

- 硬约束。
- 先验默认值。
- 开放变量。
- 相对父级的变化。
- 继承合成后的最终结果。

### 交付物

- `model/constraint-operators.json`
- 继承合成规则说明
- 冲突处理规则
- 循环依赖处理规则

### 验收标准

- [ ] 每种操作都有确定语义。
- [ ] 同一字段发生多层变化时，最终值可确定。
- [ ] `default` 和 `fix` 能被明确区分。
- [ ] `extend` 和 `override` 能被明确区分。
- [ ] 多母型组合发生冲突时有明确处理方式。
- [ ] 图谱中不允许形成循环继承。
- [ ] 节点不能用自由文本绕过正式约束字段。
- [ ] 每一条正式分析都能定位到某个公式字段。

# 四、阶段确认点

制作过程中只在以下阶段要求内容确认：

## 确认点 A：公式确认

确认阶段 1～3：

- 正式公式。
- 变量名称。
- 枚举类型。
- 变量详情结构。

## 确认点 B：继承规则确认

确认阶段 4～5：

- 约束操作。
- 多母型组合。
- 冲突处理。
- 公式指纹合成。

## 确认点 C：首条完整链确认

确认阶段 8～10：

```text
双峰多巴胺
  →
Slot
  →
幸运房东型 Slot 构筑
  →
幸运城市
```

## 确认点 D：发布前确认

确认阶段 12：

- 内容是否准确。
- 图谱是否容易理解。
- 是否可以开始第三部分游戏库。

# 五、完成定义

第一版新网站只有同时满足以下条件，才视为完成：

1. 体验模型公式及变量字典完整。
2. 每个变量都有可独立阅读的详情。
3. 原型图谱支持多个机制母型。
4. 原型图谱支持任意深度的原型/变体。
5. 原型图谱支持跨母型组合。
6. 每个节点都有公式指纹和父级差异。
7. Slot → 幸运房东型 → 幸运城市完整跑通。
8. 第一、二部分不依赖游戏库即可成立。
9. 新版与旧版文件、数据和代码完全解耦。
10. 内容、结构、技术和视觉验收全部通过。
