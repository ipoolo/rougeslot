# Slot改·战斗型：游戏变体改动维度草稿

- 状态：待人工确认
- 版本：2026-08-01 draft.1
- 范围：`prototype.slot-transform-combat` 下 11 个游戏变体
- 数据来源：`category-variants.json` 中已确认的九字段描述
- 原则：本草稿不回写九字段；未知内容保持“待确认”，不根据题材包装强行推断机制。

## 0. 分析目的

这份维度矩阵不是最终分类结果，也不是为了给游戏增加一组孤立标签。它是分析「Slot改·战斗型」品类原型的证据层，最终需要回答四个问题：

1. **品类原型不变量**：11 个变体共同保留了什么，失去哪些结构后就不再属于这个品类。
2. **主要改动分支**：游戏分别从 Random、Put、Show_TP、C₁、C₂、战斗关系、资源与操作方式向哪些方向扩展。
3. **分支的体验代价**：每种改动如何影响操作数、认知负荷、揭晓集中度、支付线密度与双峰连续性。
4. **品类生态结构**：每条分支由哪些代表游戏支撑，哪些分支已经形成稳定解法，哪些仍是高风险尝试或品类边界。

确认后的产出链路为：

> 变体字段证据 → 独立改动维度 → 改动方向聚类 → 品类原型不变量／可变参数 → 代表游戏与体验代价 → 品类生态

因此维度是否保留，不取决于它能否描述某个游戏，而取决于它能否帮助解释品类原型的分化方向与设计边界。

## 3. 待人工确认的冲突与缺口

已确认并完成的数据修正不再列入。以下项目会影响维度矩阵，需继续确认：

1. **Rogue Slots 的防御层**
   - `C₂` 标签写“攻防血”，正文写“攻血”。
   - 需要确认是否存在独立于生命值的防御／护甲。

2. **Spinny Dungeon 的防御层**
   - `C₂` 标签写“攻防血”，正文写“攻血”。
   - 需要确认是否存在独立防御，还是只有双方生命与食物压力。

3. **Hoptale Demo 的战斗关系**
   - 已确认敌方符号入池、进入 1D 盘面并参与 `C₁/C₂`。
   - 尚不能判断是“只有我方攻击”还是“敌我互攻”。

4. **Hoptale Demo 的单轴控制归属**
   - `Show_TP` 说明因单轴控制而改为 1D，但 `Random` 仍是直接抽取，`Put` 仍是自动落位加敌方入盘。
   - 需要确认玩家究竟在哪个阶段控制单轴。

5. **Slot or Not 的敌方落位**
   - 敌方已进入 `Pool_Symbol`，但 `Put` 仍写具体表现待确认。
   - 需要确认敌方是否与我方装备进入同一可协同盘面。

6. **魔法与能量是否统一为一个资源大类**
   - 推荐数据层使用“技能资源”大类，再保留 `魔法／能量` 子类型。
   - 若两者机制本质不同，则保持两个一级维度取值。

7. **`C₁` 输出缺口**
   - 「拉杆战士：弓箭与魔法」与「Hoptale Demo」没有明确说明 `C₁` 输出是战斗布局还是单回合战斗能力。

8. **多回合 `N` 的单位**
   - 多款游戏写为“`N >= 1` 每次战斗用回合数”。
   - 当前按“一个战斗包含多个 Spin／回合”理解；需要确认 `N` 计数单位是否就是 Spin／战斗回合。

9. **通用 BD 描述是否足以分类**
   - 狗与哥布林、拉杆英雄、拉杆战士目前只有父级式“符号池／规则／数值构筑”。
   - 第一版将其标为“待继续细分”，不推断具体养成对象。

## 4. 确认后的数据化方式

确认完成后再进入下一阶段：建立独立的 `combat-variant-dimensions.json`，保存维度定义、游戏取值、依据字段与确认状态；不把分类结论重复塞回九字段描述。

数据化之后不会直接结束，而是继续生成品类生态需要的四层结构：

1. **CORE｜原型核心**：所有主流变体共同依赖的公式结构与体验承诺。
2. **BRANCH｜改动分支**：空间拓扑、C₁ 协同、敌方盘面化、战斗生存化、资源化与交互化等主要方向。
3. **CASE｜代表案例**：每条分支的代表游戏、字段证据、收益与代价。
4. **BOUNDARY｜边界与风险**：操作过载、认知复杂度、揭晓峰值稀释，以及可能脱离品类原型的组合。

## 5. 最终交付：品类生态位图

`CORE／BRANCH／CASE／BOUNDARY` 不是四个彼此分离的最终页面，而是同一张生态位图的四种分析镜头。完整地图始终可见，选择镜头时只聚焦对应的游戏、分支、关系和解释。

### 5.1 第一版坐标建议

- **横轴｜单 Spin 玩家介入强度**：自动抽取与自动落位 → 候选选择 → 逐轴控制 → 逐符号／手动战斗序列。
- **纵轴｜战斗与生存状态复杂度**：只有我方攻击的数值检测 → 敌我互攻 → 攻防血 → 魔法／能量／食物等多资源生存。

这两个轴直接对应品类原型最重要的体验分化：玩家在一次 Spin 中要做多少事，以及战斗结果需要理解多少状态。

### 5.2 其他维度的视觉编码

- **节点形状｜Show_TP**：2D 固定网格／2D 成长网格／1D 序列。
- **节点颜色｜敌方空间参与**：盘面外目标／固定敌方区域／敌方符号进入同一盘面。
- **节点描边｜C₁ 协同**：阵容邻接／支付线／混合协同／敌方参与协同。
- **分支区域｜主要生态位**：数值检测、自动生存战斗、盘面敌我协同、手动控制、资源生存等。
- **节点大小｜市场验证，可选**：只有在销量、评价量或其他市场数据覆盖足够完整并确认口径后才启用；否则所有游戏保持同尺寸。

### 5.3 地图交互

- 默认显示完整品类生态，不因筛选隐藏上下文。
- 点击游戏节点，显示其九字段证据、维度取值、相对原型的修改路径和体验代价。
- 点击改动分支，聚焦该分支的代表游戏及从原型到分支的关系。
- 提供 `CORE／BRANCH／CASE／BOUNDARY` 四类镜头，并同步更新解释面板。
- 支持按 `1D／2D`、支付线／阵容、敌方入盘、资源类型、操作粒度等维度聚焦。
- 所有未确认游戏继续显示，但带“待确认”状态，不强行落入确定生态位。

### 5.4 地图需要回答的问题

1. 哪些游戏最接近品类原型核心，哪些游戏正在向边界移动？
2. 当前品类形成了哪些稳定生态位，分别由哪些游戏代表？
3. 每条分支通过修改哪些公式字段获得差异，又付出了什么体验代价？
4. 哪些生态位已经拥挤，哪些组合仍然空缺？
5. 哪些高复杂度组合正在破坏 Slot 的集中揭晓与双峰连续性？
