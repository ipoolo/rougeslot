00 · 原型图谱分析架构

一套体验模型，如何向下
分化成多个机制与品类

这不是一条固定的 Slot 链。每个父节点都可以拥有多个子节点； 每条分支仍然回到同一组体验公式字段，记录自己新增或改变的约束。 Slot 母体目前先按“怎样继承核心 × 结果怎样表现”分成四个品类原型。

共同分析底座 P(t) ⟦ [ Random @ Pool_Symbol → Put @ Show_TP → Combo(C₁ → C₂) @ Show_TP ]ₙ → BD ⟧ P(t) 是可选外层目标压力；每条分支都要说明它是否启用、如何检查，以及它与 N 的区别。
最重要的结构规则 每一层向下都是一对多：一个父节点，可以分化出多个子节点。

子节点继承父级已有约束，只记录自己进一步固定、收窄、扩展、覆写或禁用的字段。

02 · 洞察二

C₂ 是基于 C₁ 结果的二次揭晓
不是结算动画，也不是重新开奖

C₁ 首先建立本次结果的价值锚点，让玩家知道“这次大概抽得怎么样”。 C₂ 不推翻或重置 C₁，也不引入一套与 C₁ 无关的新结果；它是在 C₁ 已经确定的基础上， 通过过程逐步释放结果信息，让玩家持续预测：“这次好结果，最终能兑现得多好？”

C₁ 建立价值锚点 我已经知道“这次抽得不错”
→
C₂ 二次揭晓 C₁ 的兑现程度 但还不知道“最终能兑现得多好”
→
Spin_Result 最终封闭 结果被完整确认

只是结算动画只有确定结果的播放，没有期待。

接近重新开奖推翻 C₁，或引入与 C₁ 无关的新随机。

有效的 C₂保留不确定性，但它必须来自 C₁ 结果的后续展开。

BAD CASE

没有延续 C₁ 的二次揭晓

结果过早封闭，只剩答案播放；转入策略规划，也无法延续结果期待。

BAD CASE 01拉杆英雄 · Slot改
12 攻击+8 增益=20 伤害

确定答案的播放

血量与攻击力已经直接展示，玩家在战斗开始前就能算出结果。 后续表演没有预测变化，只是在播放一个已经知道的答案。

第二峰风险：主观不确定性接近于零
BAD CASE 02帝国轮盘 · Slot+数值
Slot 产出→资源数值→文明策略→规划决策

策略接管了 C₂，却没有再次开奖

它属于 Slot+数值型变体，但 C₂主要表现为类文明的资源分配与策略经营。 玩家进入的是分析和规划状态，而不是等待未知结果逐步揭晓，因此第二峰表现较弱。

第二峰风险：有策略深度，但缺少结果期待过程
BAD CASE 03PegLotto!
C₁ 结果→重置起点→弹珠长时演算→新结果

C₂ 推翻 C₁，接近重新开奖

C₁ 建立的结果价值没有被延续；进入弹珠机后，结果由新的弹射过程重新决定。 表演时间长、路径与碰撞复杂，玩家更像开始第二场独立开奖，而不是等待 C₁ 兑现。

第二峰风险：C₁ 价值被重置 + 过程过长
GOOD CASE

沿 C₁ 结果继续揭晓

每一步都承接 C₁，逐步揭晓兑现程度，直到 Spin_Result 封闭。

GOOD CASE 01Slotbound · Slot+
多兵种→位置／顺序→局部交互→胜负？

紧凑的二维战斗时序

传统 Slot C₁继续承担第一峰；C₂不直接提前展示全部数值， 而是通过战斗过程分批揭晓结果，让胜负预测持续变化。

第二峰来源：可理解因果 + 尚未封闭的结果
GOOD CASE 02魔王终局 · Slot改
阵形→相邻交战→连续反应→结果

把数值加减变成空间战斗揭晓

C₂的二维紧凑战斗强化了第二峰；但战斗与组合共用棋盘， 会提高 C₁的大奖识别复杂度，因此必须控制棋盘与关系规模。

核心取舍：强化 C₂，同时保护 C₁
规则 02 C₂ 必须继承 C₁ 的价值锚点，并逐步揭晓它最终能兑现到什么程度。

第二峰来自“我已经知道自己抽得不错，但还不知道最终能兑现得多好”，而不是系统突然增加另一套随机结果。

03 · 设计检查

把洞察变成
可验证的问题

这些问题用于检查新原型，而不是把洞察固化成不可调整的数值上限。

CHECK 01 · C₁

第一次看就能判断好坏吗？

不解释规则，让玩家完成一次 Spin：他能否指出哪里形成了基础协同、为什么这是好结果？

CHECK 02 · C₂

暂停在 C₂开始前，答案已经算完了吗？

如果玩家能够直接准确报出最终结果，后续表演大概率只是结算动画，而不是二次揭晓。

CHECK 03 · 认知预算

棋盘是否还处在不耗力观察区？

共同检查棋盘大小、符号类型、关系层数与跨区域依赖；Slot改+战斗尤其需要控制这些变量。

CHECK 04 · 边界

复杂规则真的必须属于 C₁吗？

决定基础协同是否成立的规则留在 C₁；在基础结果之上进行修饰或转译的规则优先归入 C₂。
