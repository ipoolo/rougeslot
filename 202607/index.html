上方是玩家实际经历，下方是同一流程在体验公式中的位置；P(t) 与 N = 1 分别表示外层压力和构筑频率。

P(t) · 外层目标压力 若干次 Spin 后支付房租

房租检查决定玩家能否继续，并形成跨多次 Spin 的目标压力；它不与主流程中 “每次 Spin 后选择新符号”的 N = 1 混为同一个周期。

02 · 体验模型的抽象架构

三个体验阶段：
揭晓 → 结算 → 构筑

P(t) 作为可选外层条件包裹 Random、Put、Combo 与 BD； 内部玩家体验仍然归纳为揭晓、结算与构筑三个阶段。

00 · 原型图谱分析架构

一套体验模型，如何向下
分化成多个机制与品类

这不是一条固定的 Slot 链。每个父节点都可以拥有多个子节点； 每条分支仍然回到同一组体验公式字段，记录自己新增或改变的约束。

共同分析底座 P(t) ⟦ [ Random @ Pool_Symbol → Put @ Show_TP → Combo(C₁ → C₂?) @ Show_TP ]ₙ → BD ⟧ P(t) 是可选外层目标压力；每条分支都要说明它是否启用、如何检查，以及它与 N 的区别。
最重要的结构规则 每一层向下都是一对多：一个父节点，可以分化出多个子节点。

子节点继承父级已有约束，只记录自己进一步固定、收窄、扩展、覆写或禁用的字段。
